# KB-004 健康巡检型异常

## 典型现象

- 用户只描述“系统好像有点异常”，但没有明确落到数据库、支付或商品页面
- 多个服务同时出现轻度异常，表现为实例健康分下降、延迟升高或错误率抬头
- `gateway-service`、`auth-service`、`order-service` 等服务存在少量异常实例

## 正常指标参考

- CPU 使用率 < 80%
- 内存使用率 < 85%
- 错误率 < 1%
- P99 延迟 < 500ms

## 异常信号参考

- 日志出现 `error`、`failed`、`timeout` -> 说明存在错误或超时异常
- `service_health_score` 下降或 unhealthy instance 数增加 -> 更偏向服务健康巡检异常
- P99 延迟 > 500ms -> 说明存在服务性能退化
- 依赖异常或调用失败 -> 需要继续追踪链路定位根因

## 使用建议

- 先给出健康巡检结论，再判断是否需要继续下钻到支付、缓存、鉴权或数据库
- 只有出现稳定的慢 SQL、连接池等待或锁竞争时，才继续把根因收口到数据库
- 如果异常同时覆盖多个服务但证据不足，应保留低置信度和证据缺口说明
