# 故障模式输出模板

本文件只提供“如何整理候选模式”的输出模板，不保存正式故障规则。

优先结合下列典型模式与知识库案例进行判断：

- 数据库连接超时 -> `KB-001-数据库连接超时.md`
- 支付网关超时 -> `KB-002-支付网关超时.md`
- 内部依赖错误 -> `KB-003-内部依赖错误.md`
- 服务健康基线 -> `KB-004-服务健康基线.md`

| 候选模式 | 对应知识 | 已确认的直接证据 | 还缺什么证据 | 当前保留意见 |
|---|---|---|---|---|
| 模式 A | KB-xxx | 日志/指标/链路事实 | 还需补的证据 | 目前不能下结论的原因 |
| 模式 B | KB-xxx | 日志/指标/链路事实 | 还需补的证据 | 目前不能下结论的原因 |

## 使用建议

- 先从知识库命中最接近的模式开始，不要在这里直接发明新模式。
- 如果多个模式同时成立，优先输出最能被当前证据支持的那个。
- 依赖关系优先参考：`frontend -> order-service -> product-service -> inventory-db` 和 `order-service -> payment-service -> external-payment-gateway`
